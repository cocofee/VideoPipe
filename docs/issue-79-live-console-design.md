# Issue #79 现场视频工作台设计

## 目标

VideoPipe 的主界面服务于终点现场操作，不承担正式计时、成绩计算或名次发布。操作员在比赛进行中持续完成三件事：观察实时视频、确认新产生的视频事件、修正号码或作废错误事件。

CycleRace 仍是唯一正式计时、成绩和名次来源。VideoPipe 保存视频事件、号码候选和证据图片，用于现场核对及争议取证。

## 现场工作流

1. 选择赛事并开始采集。
2. 左侧持续显示实时视频，新事件写入右侧事件队列。
3. 操作员点击事件，在右侧下方直接查看已保存证据。
4. 号码正确时无需操作；号码缺失或错误时输入号码并选择“保存并下一条”。
5. 误检事件可标记作废；OCR 失败不得删除事件或证据。
6. 停止采集后保持当前工作台和选择状态，不切换到单独的“停止后复核”页面。

新事件不得改变操作员当前选择或滚动位置。只有当前没有选择时，界面才可默认选中第一条事件。

## 最终结构

```text
+--------------------------------------------------------------------------------+
| 视频取证工作台 | 当前赛事 | 采集状态 | 主相机状态                              |
+-----------------------------------------------+--------------------------------+
|                                               | 事件队列                        |

|                                               | 快速核对 | 当前事件信息          |
```

## 信息层级

### 主工作区

- 实时视频：占据主要面积，优先保证目标、终点线和检测框清晰可见。
- 事件队列：只显示视频系统自身的顺序、号码、视频过线时间、处理状态和可选机位。
- 快速核对：显示当前事件已保存的真实证据，并提供号码修正和作废。
- 采集控制：只保留开始/停止和关键状态，不展示模型路径、号码规则或诊断工具。

## 视觉规范

- 使用微软雅黑 UI / Segoe UI 作为工作台字体，正文以 12-13px 为主，避免旧界面全局 16px 造成拥挤。
- 保持白色工作面板、浅灰应用背景和深色视频画布，不使用大面积高饱和品牌色。
- 绿色只表示开始或正常运行，红色只表示停止、作废、冲突和未识别，蓝色只表示保存等明确主操作。
- 号码列保持深色高对比文本，状态语义集中在状态列，避免同一行同时出现多种红绿强调。
- 顶部呈现赛事和采集状态，底部呈现操作；状态栏只保留运行性能、OCR 和巡检信息，不重复相机与事件数量。
- 横向和纵向分隔条保持可拖动，并使用稳定宽度，方便 16 英寸笔记本现场调整视频与核对区域比例。

### 现场设置

以下功能保留，但不占用主工作区：

- 模型选择和重载。
- 标定预设保存和加载。
- 模拟测试、号码去重、名单过滤、纯数字、龙门安全模式。
- 号码段设置、发枪时间设置。
- 重置检测统计、清空记录、诊断问题标记。

“诊断问题标记”仍表示保存当前原始帧和运行上下文，不改名为“补记冲线”。第一版不实现人工补记冲线事件。

## 状态语义

- 停止采集后统一显示“采集已停止 / 主相机待机 / -- FPS / 巡检待机”，不得继续展示上一轮运行状态。
- 仅视频检测模式显示“OCR 已关闭”并禁用 OCR 启动入口，不使用“未初始化”描述主动关闭的能力。
- 队列筛选使用“全部 / 需处理”双段按钮，并在按钮内显示对应数量。
- 底部“本轮新增”只统计本次采集启动后的事件，与队列全部记录数明确区分。
- 操作员正在核对旧事件时，新事件只显示“新增 N 条”提示；点击提示才跳转，不自动改变当前选择。
- `已识别`：已有可用号码，不代表正式成绩已确认。
- `待核对`：OCR 给出候选，但需要人工确认。
- `未识别`：事件和证据已经保存，但没有可用号码。
- `号码冲突`：同一号码对应多个未作废视频事件，需要人工检查。
- `已作废`：视频事件被人工排除，证据仍保留。

“需处理”包含未作废的待核对、未识别及号码冲突事件。

## 证据与性能边界

- 第一版不增加视频回放和额外实时解码。
- 快速核对最多展示 5 张现有证据，包括全景、原始帧、运动员裁剪、号码裁剪和号码候选。
- 界面不得把这些图片描述为连续视频帧。
- 证据缺失时显示稳定空状态，不阻塞事件列表或采集线程。
- 图片只在操作员选择事件时加载，不在新事件到达时主动刷新当前核对区。

## 暂不实现

- 视频片段回放或逐帧播放。
- VideoPipe 内正式名次、组名次、芯片时间核对和时间差计算。
- CycleRace 名单、发枪时间、名次的自动联动。
- 分组成绩册生成。
- 人工补记冲线事件。

这些能力如后续实施，应单独评估数据权威边界、现场网络条件、存储量和笔记本实时解码负载。

## 验收标准

- 1200 x 768 最小窗口下主控件不重叠；16 英寸常见分辨率下视频仍是第一视觉区域。
- 主界面不再出现 `RANK / TIME / ID` 大屏条和模型路径工具栏。
- 系统日志不占用现场工作区，但后台日志记录继续工作。
- 点击事件只更新嵌入式快速核对区，不强制打开独立窗口。
- 新事件到达时不改变已经选中的事件。
- 停止采集后事件队列和快速核对区保持可用。
- 修改号码、作废和取消作废继续使用现有数据库接口。
- OCR 失败或证据文件缺失时，事件仍然可见且界面稳定。
