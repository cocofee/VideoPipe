# 独立计数验证记录

本分支在干净检出上验证，未依赖原工作区的未提交检测/OCR改动。既有 `Detector` 仅增加独立出口、显式帧元数据及计数专用早返回；OCR 依赖延后到旧 `load_model`，匿名服务无需加载 OCR。

验证环境：Python 3.12；Ultralytics 8.4.174、NumPy 1.26.4、OpenCV 4.11.0.86、PyQt5 5.15.11、pytest 9.0.2。实片使用本地 `yolo26n.pt`，模型与原录像未上传。

| 检查 | 结果 |
| --- | --- |
| `tests/realtime` | 40 项通过 |
| FinishReview 相关 UI、芯片接收及打包契约测试 | 169 项通过 |
| 清晰三人集团，33 帧、1280 输入 | 视频 3，冻结视觉真值 3；次数验证通过 |
| 密集集团，126 帧、1280 输入 | 视频 3，视觉至少 6；验证失败 |
| 原录像＋合成芯片完整服务 | 等数质量异常补扫，导出证据并保留未决 |
| 重启后注入芯片撤销 | 视频保持 3，芯片 3→2，差异变为 1；相机 UID 数保持 6 |
| 内存原帧被淘汰 | 从原始录像读取并补扫 |

[实片摘要](sprint_summary.json)记录计数、质量原因与实际 tracker 配置。[闭环摘要](integration_summary.json)记录合成注入检查，不代表真实芯片漏读准确率。

原始录像、包含运动员画面的联系表、绝对本地路径、完整运行日志及模型权重没有提交。`fixtures/` 的视频路径是占位符：验证者须提供对应原录像路径和本地模型后执行 `tools/validate_independent_sprint.py`。期望值只在独立推理完成后用于评分；检测和计数过程不读取芯片。

密集片段没有冻结完整逐人真值，所以“视觉至少 6”只能证明现有 3 次计数失败，不能用下界相等宣布通过。低阈值实验得到更多计数但也增加异常轨迹，没有提升为默认参数。首版密集集团准确率、峰值直播性能和人工量验收仍未完成。
